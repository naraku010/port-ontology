# 설계 결정

각 항목은 "무엇을 정했나 / 왜 / 바꾸려면"입니다. 되돌리기 전에 이유를 먼저 확인하세요.

## D1. 도메인: 컨테이너 터미널(터미널 운영사 관점)

- **결정**: 선사 관점(선대·항로 최적화)이 아니라 터미널 관점(선석·장치장·환적)으로 모델링했습니다.
- **이유**: 지연이 선석 → 후속 선박 → 환적 → 화주로 연쇄되는 구조가 관계 그래프 추론을 보여주기에 좋고, 제원·위험물·냉동 같은 제약 규칙이 풍부합니다. 선사 관점은 온톨로지보다 최적화 문제에 가깝습니다.

## D2. LLM은 쿼리를 쓰지 않고 도구만 고른다

- **결정**: 자연어 → Cypher/SPARQL 생성 방식을 쓰지 않습니다. 추론은 Rust 코드가 결정적으로 수행하고, LLM은 MCP 도구를 고르고 결과를 설명합니다.
- **이유**: 생성된 쿼리는 틀리기 쉽고 검증이 어렵습니다. 온톨로지가 LLM의 행동 범위를 제한한다는 설계 의도가 드러나고, 같은 질문에 항상 같은 답이 나옵니다.

## D3. 로컬 LLM CLI + MCP stdio, 같은 exe가 겸함

- **결정**: 사용자는 로컬 CLI(예: Claude Code)를 씁니다. 앱 exe가 `--mcp`로 실행되면 MCP 서버가 됩니다.
- **이유**: CLI exe 자체에 코드를 넣을 수는 없지만, MCP stdio 방식이면 CLI가 우리 exe를 자식 프로세스로 띄워 사실상 "백엔드를 심은" 효과가 납니다. 서버를 따로 띄우거나 포트를 열 필요가 없습니다.

## D4. UI와 MCP가 같은 디스패처를 쓴다

- **결정**: Tauri command는 `call_tool`, `list_tools` 두 개뿐입니다. UI 기능은 모두 MCP 도구로 구현합니다.
- **이유**: 사람이 누르는 버튼과 LLM이 부르는 도구의 동작이 어긋나지 않습니다. MCP 탭의 도구 콘솔로 LLM이 볼 결과를 그대로 재현할 수 있습니다.

## D5. 상태 변경은 propose → apply 2단계

- **결정**: 바로 상태를 바꾸는 도구는 없습니다(`reset_data` 제외). `propose_*`가 규칙을 검증하고 plan_id를 발급하며, `apply_plan`이 반영 직전에 다시 검증합니다. 적용 내역은 감사 로그에 남습니다.
- **이유**: LLM이 사용자 확인 없이 운영 데이터를 바꾸지 못하게 하고, 제안과 적용 사이에 상태가 바뀌어도 안전합니다. `readOnlyHint`로 CLI 자동 허용 범위를 나눌 수 있습니다.

## D6. 그래프 DB 없이 Rust 구조체 + BTreeMap

- **결정**: Neo4j, Jena, Kùzu 같은 그래프 DB를 쓰지 않고 인메모리 구조체로 표현했습니다. 관계는 ID 필드이고 `get_entity`가 간선으로 펼칩니다.
- **이유**: 데이터가 작고(컨테이너 수백 개), 설치형 exe 하나에 넣어야 합니다. Neo4j는 별도 서버가 필요해 맞지 않습니다. BTreeMap은 순회 순서가 고정이라 결과가 결정적입니다.
- **바꾸려면**: 데이터가 커지거나 임의 쿼리가 필요해지면 임베디드 그래프 DB(Kùzu 등)나 SQLite를 검토합니다. 그 경우에도 D2(LLM은 쿼리를 쓰지 않음)는 유지합니다.

## D7. 지연된 배도 접안 순번을 유지한다

- **결정**: 같은 선석에서 앞 배가 늦어지면 뒤 배들이 밀립니다. 늦은 배가 순번을 잃고 뒤로 가는 정책이 아닙니다.
- **이유**: 근거 경로가 "원인 → 결과" 한 방향으로 명확해집니다. 실제 터미널은 계약(berth window)에 따라 다르므로, 정책을 바꾸려면 `propagate`의 정렬 기준만 고치면 됩니다.

## D8. 시드 데이터는 가상 + 결정적

- **결정**: 실제 선사·선박·화주 이름을 쓰지 않고, 고정 시드로 생성합니다.
- **이유**: 실존 기업을 연상시키지 않고, 테스트와 문서의 수치가 고정됩니다. 선석 간격과 환적 여유 시간은 지연이 적당히 연쇄되도록 조정했습니다. B6 예비 선석은 대안 제시가 나오도록 일부러 비워 두었습니다.

## D9. 프론트: Next.js 정적 export + Tailwind + zustand, 그래프는 직접 SVG

- **결정**: 사용자가 지정한 스택입니다. 영향 그래프는 React Flow 같은 라이브러리 없이 SVG 계층 배치로 그렸습니다.
- **이유**: Tauri는 정적 파일을 서빙하므로 SSR이 필요 없습니다. 영향 그래프는 연쇄 깊이(level)가 이미 계산된 DAG라 단순 계층 배치로 충분하고, 의존성과 번들 크기를 줄였습니다.

## D10. 식별자는 영어, 표시는 한국어

- **결정**: 클래스·관계·도구·규칙 ID와 JSON 키, enum 값은 영어로 두고, 사용자에게 보이는 메시지와 UI는 한국어로 씁니다.
- **이유**: 식별자는 LLM·코드·문서가 공유하는 계약이라 안정적이어야 하고, 사용자는 한국어 화면을 원합니다. 프론트의 `labels.ts`가 변환합니다.
